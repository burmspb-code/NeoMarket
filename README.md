# NeoMarket 🔐🛒

Профессиональный интернет-магазин дверных замков, фурнитуры и аксессуаров, построенный на базе веб-фреймворка Django.

## 🛠️ Экосистема проекта (4 Рабочих Приложения)

Архитектура проекта строго разделена на изолированные модули согласно лучшим практикам разработки:
1. **`catalog`** — витрина товаров, управление категориями, замками и фурнитурой.
2. **`blog`** — публикации, статьи и маркетинговый контент для привлечения клиентов.
3. **`mailings`** — асинхронный сервис автоматических и ручных email-рассылок.
4. **`users`** — кастомная модель пользователей (авторизация по Email) и личные кабинеты.

## 🚀 Инструкция по локальному развертыванию проекта (Ручной запуск)

Для проверки проекта на локальной машине выполните следующие стандартные шаги в терминале вашей среды разработки:

### Шаг 1. Подготовка окружения и файлов конфигурации
1. Убедитесь, что в системе установлен менеджер пакетов **Poetry**.
2. Убедитесь, что локальный **Redis-сервер** запущен на вашем компьютере на стандартном порту `6379`.
3. Создайте в корне проекта файл **`.env`** на основе демонстрационного шаблона `.env.sample`. Для локальной проверки параметры базы данных (`DB_NAME`, `DB_USER` и т.д.) оставьте **пустыми** [Template].

### Шаг 2. Установка зависимостей проекта
Установите все необходимые библиотеки проекта в виртуальное окружение:
```bash
poetry install
```

### Шаг 3. Инициализация базы данных и миграции
Проект настроен на гибридную работу с СУБД. Поскольку параметры PostgreSQL в `.env` оставлены пустыми, Django автоматически развернет изолированную локальную базу данных **SQLite** (`db.sqlite3`) [Template]. Накатите структуру таблиц и примените Data-миграции ролей:
```bash
poetry run python manage.py migrate
```

### Шаг 4. Загрузка демонстрационных данных (UTF-8 фикстур)
Поочередно загрузите готовый контент для каждого модуля интернет-магазина. Файлы выгружены с принудительным использованием флага `-Xutf8`, что гарантирует отображение чистого русского текста без «кракозябр» на Windows [Template]:
```bash
poetry run python manage.py loaddata product_fixture blog_fixture mailings_fixture
```

### Шаг 5. Создание учетной записи Администратора
Запустите кастомную консольную команду для безопасной и идемпотентной инициализации профиля суперпользователя:
```bash
poetry run python manage.py createadmin
```
*Данные для входа в панель администратора по умолчанию: Логин (Email): `admin@neomarket.local` | Пароль: `admin` [Template].*

## ⚙️ Запуск экосистемы NeoMarket (Синхронизация процессов)

Для полноценной проверки асинхронной отправки писем, работы планировщика и фиксации журнала логов, пожалуйста, откройте **3 независимых окна терминала** и запустите процессы:

1. **Терминал №1 (Веб-сайт Django):**
   ```bash
   poetry run python manage.py runserver
   ```
   *Сайт будет доступен по адресу: `http://127.0.0`, панель администратора: `http://127.0.0admin/`.*

2. **Терминал №2 (Фоновый воркер Celery — обработчик отправки писем):**
   ```bash
   poetry run celery -A config worker --loglevel=info --pool=threads
   ```
   *Использует потоковый пул `threads` для стопроцентной совместимости с ОС Windows и Python 3.14.*

3. **Терминал №3 (Робот-планировщик Celery Beat — отслеживание времени):**
   ```bash
   poetry run celery -A config beat --loglevel=info
   ```

## 🔑 Разграничение прав доступа (RBAC)

Вся ролевая модель безопасности вшита непосредственно в код проекта на уровне Data-миграции `0003_create_groups.py`. При выполнении миграций у вас в системе автоматически настроятся две группы пользователей [Template]:

* **Группа «Контент-менеджеры»:**
  * Имеют полный доступ к наполнению `catalog`, `blog` и запуску `mailings` [Template].
  * Защита витрины: права на жесткое удаление (`delete`) категорий и товаров у них изъяты. К приложению `users` доступа нет.

* **Группа «Модераторы»:**
  * Имеют доступ к `catalog` и `blog` строго в режиме просмотра и изменения (для скрытия нарушающего контента через флажки публикации), без прав на создание и удаление [Template].
  * Имеют точечное право `change_customuser` в приложении `users` для блокировки и деактивации учетных записей нарушителей [Template]. Доступа к приложению маркетинговых рассылок нет.

## 💎 Особенности высоконагруженной архитектуры модуля рассылок

* **Поклиентский цикл отправки (ТЗ):** Робот перебирает получателей в цикле персонально [Template]. Сбой отправки или блокировка одного Email не влияет на других клиентов, а в «Журнал логов» записываются детальные персональные отчеты по каждому адресату (ФИО, Email, статус доставки) [Template].
* **Транзакционный щит от дублей:** На уровне фоновых тасок внедрена атомарная защита `@transaction.atomic` и блокировки строк `select_for_update()`. Это полностью исключает повторную отправку писем и дублирование логов при микрозадержках сети на Windows-платформах и старых версиях Redis [Template].
* **Низкоуровневый кэш (High Performance):** Контроллеры переопределены на работу с Low-Level Cache API в Redis [Template]. Страницы детального просмотра рассылок и списки категорий каталога выдают **100% Cache Hits**, разгружая сервер и отдавая данные за ~4-5 миллисекунд. Инвалидация (сброс) кэша работает точечно по ID объекта при его сохранении.
